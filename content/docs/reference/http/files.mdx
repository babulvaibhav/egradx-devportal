/egradx/files/**: uploads, the files of a record, downloads and deletes, and the profile photo. The same endpoints in Java, Node and Python, mounted under your application's base path; every refusal is the [error envelope](/docs/reference/errors). Generated from `contracts/openapi/files.yaml`.

## Files

Upload, list, download and delete files in the signed-in person's organization. Needs a signed-in session in an organization. Files of another organization answer 404.

### Set your profile photo

```http
PUT /egradx/auth/my/profile/photo
```

Multipart `file`: PNG, JPEG or WebP, at most 5 MB by default. Replaces the earlier photo and returns the profile, whose `photoUrl` is the photo's `/egradx/files/{id}/content`, readable by everyone in the organization. Needs a signed-in session in an organization. Refuses with `FILE_EMPTY` (400), `FILE_TOO_LARGE` (413) and `FILE_TYPE_NOT_ALLOWED` (415).

**Body:** object

| Answer | Body |
|---|---|
| 200 OK | [EgradxUserProfileDto](#egradxuserprofiledto) |

### Remove your profile photo

```http
DELETE /egradx/auth/my/profile/photo
```

Deletes the photo and clears `photoUrl`. Needs a signed-in session.

### Upload a file

```http
POST /egradx/files
```

Multipart: `file`, and optionally `purpose` (default `attachment`), `attachedType` and `attachedId` (the application record it belongs to; both or neither). Needs `egradx.file.write`, or the record's access check allowing it. Refuses with `FILE_EMPTY` (400), `FILE_TOO_LARGE` (413), `FILE_TYPE_NOT_ALLOWED` (415), `FILE_REJECTED` (422) and `FILE_STORAGE_UNAVAILABLE` (503).

### Download a file

```http
GET /egradx/files/{fileId}/content
```

The bytes, with `Content-Disposition` (inline for images and PDF), `ETag` and `Accept-Ranges`; one `Range` answers 206. With pre-signed downloads on, a 302 to a short-lived URL instead. Refuses with `NOT_FOUND` (404), `ACCESS_DENIED` (403) and `FILE_STORAGE_UNAVAILABLE` (503).
