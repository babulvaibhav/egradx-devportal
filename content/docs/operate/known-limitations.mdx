The guides list each capability's limits where they apply. This page collects them all. [Parity](/docs/reference/parity) shows how far each language has each capability.

## Everywhere

| Area | Limitation |
|---|---|
| Database | PostgreSQL only. |
| Versions | Every package is 1.0.0 until the SDK is complete; fixes are republished under the same number ([upgrading](/docs/operate/upgrading)). |
| Sign-in | Providers (Google, Zoho, OpenID Connect) are set for the whole application: no single sign-on per organization, no SAML, no second factor yet. Sign-up makes a new organization; joining an existing one takes an invitation ([sign-in methods](/docs/guides/sign-in-methods)). |
| Keys | No JWKS endpoint, tokens carry no `kid`, and keys don't rotate on their own. Instances starting together on an empty keys folder can each make keys: start one first. |
| Service tokens | The SDK's sign-in doesn't issue client-credentials tokens, and treats non-person tokens as anonymous ([call another service](/docs/recipes/service-token)). |
| Several instances | Without `egradx-redis`, the role cache (60 s), live notification streams and the sign-in attempt limit are per instance ([several instances](/docs/operate/multiple-instances)). |
| Tenancy | No row-level security: your queries must filter by organization. |
| Files | One request per upload, up to `max-size`: no resumable or chunked upload yet. Profile photos are one per person, readable only in the organization they were uploaded in. No image resizing or thumbnails. No scanner ships, only the hook. Local disk with several instances needs one shared folder ([files](/docs/guides/files#guarantees-and-limits)). |
| Audit | Append-only against the application, not tamper-evident against the database's owner. |
| Notifications | At least once: a delivery can be sent twice. Slack, Twilio and Meta are tested against local stand-ins of their APIs. |
| Events | No order promised. No replay tool. No metrics for dead events. Kafka has no TLS or SASL settings. In-process with two different services on one database loses events. |
| Health | No health endpoint of the SDK's own (Java uses Actuator's). |
| Testing | No test kit yet ([testing](/docs/guides/testing)). |

## Java

- An advice of the application's own with a catch-all `@ExceptionHandler(Exception.class)` answers before the SDK's fallback, so it must handle `AccessDeniedException` too, or refusals become 500s ([errors](/docs/guides/errors#wiring-the-envelope-in)).
- `ServerException` with a status outside 400–599 answers 500 (Node and Python throw), and Java's exceptions take no `details`.
- The private key files are written owner-only where the file system has POSIX permissions; on Windows they get the folder's default permissions.
- The keys folder key must be written `keystorePath`; `keystore-path` isn't read.
- gRPC and WebFlux support is partial ([Java-only modules](/docs/guides/java-only)).
- File storage on S3 needs `software.amazon.awssdk:s3` added by the application; with `egradx.files.backend: s3` and no client, the application doesn't start.

## Node and Python

- Audit retention periods take a single unit (`7y`, `90d`); a wrong one is reported when the purge runs, not at start-up.
- The notification secrets passphrase falls back to environment variables only, not to the keys passphrase passed in code.
- Events are a separate package with their own start (`events.start()`). `migrateEgradx` / `migrate_egradx` create its tables when the package is installed.
- Kafka retry backoff isn't capped.
- Python: dates in event `data` must be ISO strings you write yourself.
