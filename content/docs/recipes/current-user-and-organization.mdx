## In background work

The caller lives in request-scoped storage. Work that runs later, or on another thread, doesn't see it:

| | Java | Node | Python |
|---|---|---|---|
| Held in | a thread-local | `AsyncLocalStorage` | a `ContextVar` |
| Promises / tasks started in the request | — | see it | see it |
| `@Async`, executors, other threads | see nothing | — | — |
| Timers, consumers, jobs started outside a request | see nothing | see nothing | see nothing |

So capture the ids in the request and pass them along: as job arguments, in the event's `organizationId`, or in the message. An event handler reads the organization from the event, never from "the current caller".

## In the browser

`useAuth().session` holds the `user`, the `organizationId` and `organizationName`, the `roleName` and the session's `authorities`. It is a snapshot for deciding what to show. The server reads the caller afresh on every request.
