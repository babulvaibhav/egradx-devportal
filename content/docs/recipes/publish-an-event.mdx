The event is written to the outbox **in your transaction**. If the change rolls back, the event never existed. After the commit the relay sends it.

**Name it** `<area>.<entity>.<what-happened>.v<N>`: `notes.note.created.v1`. Publish facts, not commands. An incompatible change to `data` is a new version, published beside the old one.

Each handler runs in its own transaction, together with an inbox row, so a second delivery of the same event is dropped. A handler that throws is retried later. Keep handlers idempotent anyway, and don't assume any order.
