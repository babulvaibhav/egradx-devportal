The SDK sends the email, keeps the one-time token, and ends every session once the password changes. You supply the two forms and the link's address.

## 1. Tell the SDK where your frontend is

The email links to `<base url>/reset-password?token=…`:

| Java | Node | Python |
|---|---|---|
| `egradx.auth.links.base-url` | `auth: { links: { baseUrl } }` | `AuthOptions(links=LinkSettings(base_url=…))` |

Without it, and without working email, no reset email is sent. The request still answers 202, so the form never reveals whether an account exists.

The new password ends every session the person had, everywhere. Send them to sign in.

| Code | Meaning |
|---|---|
| `PASSWORD_RESET_EXPIRED` | the link is too old: ask for a new one |
| `PASSWORD_RESET_INVALID` | the link was used, or replaced by a newer one |
| `PASSWORD_INVALID` | the password is shorter than 8 or longer than 128 characters |

## With Next.js

The same forms work unchanged: the client sends them to `/bff`, and the backend-for-frontend passes signed-out calls through without a token.

In `proxy.ts`, let signed-out people open the pages: `bff.guard(request, { signInPath: '/login', publicPaths: ['/forgot-password', '/reset-password', '/accept-invite'] })`.

## Signed in: changing the password

That is a different endpoint: `POST /egradx/auth/my/password` with the current and the new password. It ends every *other* session and answers with fresh tokens; pass them to `useAuth().adopt(result)`.
