## What to ask

| To check | Ask | Look at |
|---|---|---|
| The audit record | `GET /egradx/audit/events?action=notes.note.created&entityId=<id>` | `before`, `after`, `changedFields`, `outcome`, `actor` |
| The notice in the bell | `GET /egradx/notifications` | the item's `notificationKey`, `title`, `body` |
| The email | the test's SMTP server | recipient, subject, body |
| The email's delivery | `GET /egradx/notifications/admin/deliveries?channel=email` | `SENT`, or `DEAD` with `lastError` |
| An event handled | whatever its handler changed | — |
| A refusal | the status and `error.code` | — |

The audit record and the notice are written in the request's transaction: they are there when the response arrives. The email and events go out **after** the commit, so wait for them. Poll with a deadline, as the tests above do, rather than sleeping a fixed time.

## Without HTTP

In a Java test with the application context, inject `EgradxAuditor` and search for the record directly (see [read the trail](/docs/recipes/read-the-trail)). In Node and Python, use `egradx.auditor.search(...)` / `sdk.auditor.search(...)`.
