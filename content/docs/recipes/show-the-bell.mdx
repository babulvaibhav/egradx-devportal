## 2. The bell

Either write it on the hook:

<RepoSnippet file="apps/egradx-devportal/examples/web-vite/src/Bell.tsx" region="web-bell" title="src/Bell.tsx" />

…or copy in the ready one, which also does paging and read state, and takes your shadcn theme:

```sh
npx shadcn@latest add https://<this portal>/r/notification-bell.json
```

Use `useInbox()` **once**, high in the tree, and pass its data down: each use opens its own stream.

## 3. Let the stream through

The live stream is `GET /egradx/notifications/stream`, server-sent events.

- **Vite in development:** the generated `vite.config.ts` already proxies `/egradx` to the backend.
- **Next.js:** the backend-for-frontend forwards it.
- **Production:** turn buffering off for that path in your reverse proxy (nginx: `proxy_buffering off;`), and allow connections of at least five minutes: the stream reconnects every five.

## Good to know

- The stream replays nothing; `useInbox` reloads the list each time it reopens, so nothing is missed.
- It lets go of the connection while the tab is hidden.
- With several instances, a notice reaches the streams open **on the instance that published it**. The others see it on their next load: see [two instances](/docs/recipes/two-instances).
