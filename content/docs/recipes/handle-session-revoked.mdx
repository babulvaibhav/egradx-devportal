## What happens

An access token lasts 60 minutes, but the SDK checks on every request that its session is still valid. When it isn't, the request gets 401 `SESSION_EXPIRED`. The client then tries to renew, once. The refresh is refused with the reason:

| Code | Why |
|---|---|
| `SESSION_REVOKED` | the person changed their password, reset it, or signed out everywhere |
| `ORG_SUSPENDED` | their organization was suspended |
| `AUTH_REFRESH_TOKEN_INVALID` | they were deactivated, or the refresh token expired (after 7 days), was revoked or is unknown |

The client ends the session and calls your `onSessionEnded(reason)`. Every guarded page then sees `isAuthenticated: false`.

## Things not to do

- **Don't retry on a 401 yourself.** The client renews once, and shares one renewal between all waiting requests. A loop of your own turns a revoked session into a storm of refreshes.
- **Don't treat a coded 403 as a session problem.** `ACCESS_DENIED` is a decision about one action. The session is fine.
- **Don't keep showing data.** When the session ends, clear what you cached for it (key caches by `sessionScope(session)`).

## With Next.js

The backend-for-frontend renews in the server. When the API refuses, it answers with the header `X-Egradx-Session-Ended` and the API's refusal as the body. The client ends its session the same way and calls `onSessionEnded` with the same codes.
