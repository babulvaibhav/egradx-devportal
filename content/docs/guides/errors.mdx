## What it is

Every failure answers with the same JSON, whichever library or language produced it:

```json
{ "success": false,
  "error": { "code": "NOTE_NOT_FOUND", "message": "There is no note 42", "timestamp": "2026-10-05T12:46:17.037Z",
             "requestId": "…", "traceId": "…", "details": { } } }
```

- **`code`** is what clients switch on. The generic ones — `NOT_AUTHENTICATED`, `ACCESS_DENIED`, `NOT_FOUND`, `CONFLICT`, `INVALID_REQUEST`, `INTERNAL_ERROR` — plus the SDK's own (`AUTH_INVALID_CREDENTIALS`, `SESSION_REVOKED`…) and yours (`NOTE_NOT_FOUND`).
- **`message`** is for people, and never parsed.
- **A 5xx never reveals anything:** its message is always "Something went wrong"; the failure is logged with its stack trace and the request id.
- **`details`** appears only for codes that carry something to act on (`ORG_SELECTION_REQUIRED` lists the organizations).

| Exception (`com.egradx.core.exception`, `@babulvaibhav/egradx-core`, `egradx.core`) | Status | Code unless you give one |
|---|---|---|
| `ValidationException`, `BadRequestException` | 400 | `INVALID_REQUEST` |
| `AuthenticationException` | 401 | `NOT_AUTHENTICATED` |
| `AuthorizationException` | 403 | `ACCESS_DENIED` |
| `NotFoundException` | 404 | `NOT_FOUND` |
| `DuplicateResourceException` | 409 | `CONFLICT` |
| `NotImplementedException` | 501 | `INTERNAL_ERROR` |
| `ServerUnavailableException` | 503 | `INTERNAL_ERROR` |
| `ServerException(status)` | the status | the generic code for it |
| anything else | 500 | `INTERNAL_ERROR` |

Node and Python exceptions also take `details`. Better than a code at each throw: a class of your own extending one of these with its code fixed, as OIM's `InsufficientInventoryException` does.

## Wiring the envelope in

<Languages>
<Tab value="Java">

The SDK's endpoints answer this way already. For **your** endpoints, add one advice extending the SDK's — every generated project has it:

<RepoSnippet file="apps/egradx-devportal/examples/java/src/main/java/com/acme/notes/ApiExceptionHandler.java" region="error-advice" title="ApiExceptionHandler.java" />

<Callout type="warn" title="Without it">
  A Java application on `egradx-sdk` alone answers its own endpoints' failures in Spring Boot's format: a `NotFoundException` becomes a 500, a validation failure Spring's `/error` body. The advice above (or `egradx-webservice`, which carries one) fixes that.
</Callout>

`EgradxExceptionHandlerSupport` already answers the core exceptions, Bean Validation (`@Valid`), a missing parameter, a malformed value or body, and Spring MVC's own refusals (unknown path, wrong method) with their statuses. Override `handleBeanValidation` for your own wording; add handlers for exceptions of yours that don't extend the core ones, using `respond(status, code, message[, details])`.

</Tab>
<Tab value="Node">

`app.use(...egradxErrors())`, after every route, answers everything: the SDK's exceptions, an unreadable body, an unknown path (404), anything else (500, logged). See `src/app.ts`. Node has no validation library of its own: check bodies and throw `ValidationException`.

</Tab>
<Tab value="Python">

`sdk.install(app)` registers the handlers: the SDK's exceptions, pydantic's validation errors (400 `INVALID_REQUEST`, naming the field), unknown paths and methods, and anything else (500, logged).

</Tab>
</Languages>
