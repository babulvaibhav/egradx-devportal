## Sealed secrets

A secret your application must store — an API key, a partner's password — kept in **one text column**, readable by Java, Node and Python alike: `v1:<salt>:<wrapped key>:<ciphertext>`. AES-256-GCM, with its key wrapped under a key derived from your passphrase (PBKDF2-SHA256, 210 000 rounds).

- Keep the passphrase out of the code and the database (an environment variable, a secret store). Changing it means opening every value with the old one and sealing it again.
- Java's `CommonUtils.encrypt`/`decrypt` (single DES) are deprecated: read an old value with `decrypt` once, and seal it again.

## Lifecycle

A component that starts when the application is ready and stops when it closes, in the order registered:

| Java | Node | Python |
|---|---|---|
| a bean extending `Control` (`start()`, `stop()`), run by `ControlManager` on Spring's refresh and close | `new ControlManager()`, `register(control)`; call `start()` once ready and `stop()` at shutdown | `ControlManager()`, `register(control)`; `await start()` / `await stop()` in FastAPI's lifespan |

## Application properties

`egradx.app.software-id`, `software-name`, `software-version`, `software-repository-name` — Java `EgradxApplicationProperties`; Node `applicationProperties()` and Python `load_application_properties()` read the same as `EGRADX_APP_SOFTWAREID`, `…SOFTWARENAME`, `…SOFTWAREVERSION`, `…SOFTWAREREPOSITORYNAME`.

## Shared enums

`UserType`, `OtpMedium`, `SmsType`, `RequestStatus`, `SoftwareStatus`, `SoftwareAccessibility`, `UserBillingActions`, `ProbeClusterType`, `EgradxEventType`: one definition in the contracts, generated into Node and Python (Python's member names are upper-cased: `UserType.HUMAN == "Human"`). Reuse them; never redeclare them.
