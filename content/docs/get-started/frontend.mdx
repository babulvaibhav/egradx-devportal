Your backend from the quickstart ([Java](/docs/get-started/quickstart-java), [Node](/docs/get-started/quickstart-node) or [Python](/docs/get-started/quickstart-python)) serves the SDK's endpoints under `/egradx/**`. The web packages are the browser side of them; they work the same whatever language the backend is in.

| Package | What it gives |
|---|---|
| `@babulvaibhav/egradx-client` | The session (sign in, renew, sign out, switch organization), a `fetch` that adds the token and renews once on a 401, typed calls for every SDK endpoint, the live notification stream, file uploads with progress and downloads with the session. No framework. |
| `@babulvaibhav/egradx-react` | `EgradxProvider`, `useAuth`, `useSession`, `<Can>`, `useInbox`, `useAttachments`, `useProfilePhoto` and a hook for every store. Headless: your UI kit, router and query library stay yours. |
| `@babulvaibhav/egradx-next` | For Next.js: a backend-for-frontend that keeps the tokens in HttpOnly cookies, a page guard for `proxy.ts`, `getSession` and `serverFetch` for server code. |
| `@babulvaibhav/egradx-ui` | Ready screens (sign-in and its methods picker, sign-up, the provider callback page, sign-in methods, the bell, the audit log, notification settings and channels, file upload, attachments, the profile photo), copied into your project with the shadcn CLI. Not a runtime dependency. |

The code on this page is the portal's two web examples, `examples/web-vite` and `examples/web-next`, the frontends of the *notes* application, on the published packages.

<Callout title="Or generate it">
  [The Initializr](/start) adds either frontend to a generated project, wired to its backend.
</Callout>

## Choose one

- **React with Vite** — a single-page app. Tokens are kept in `localStorage`, so every tab follows a sign-in; any script on the page can read them, so keep the Content-Security-Policy strict.
- **Next.js** — the browser never holds a token. It talks to the Next.js server, which keeps them in HttpOnly cookies and forwards each call to your API.

<Step>

### Install

The packages are on GitHub Packages; the `.npmrc` from [access to the packages](/docs/get-started/access) covers them.

```sh
# React with Vite
npm install @babulvaibhav/egradx-client @babulvaibhav/egradx-react

# Next.js
npm install @babulvaibhav/egradx-client @babulvaibhav/egradx-react @babulvaibhav/egradx-next
```

### Show the bell

`useInbox()` loads the inbox and keeps it live. Use it once, high in the tree:

<RepoSnippet file="apps/egradx-devportal/examples/web-vite/src/components/Bell.tsx" region="web-bell" title="frontend/src/components/Bell.tsx" />

Or copy in the ready one: `npx shadcn@latest add https://<this portal>/r/notification-bell.json`.

When the backend has [file storage](/docs/guides/files), the same client uploads and shows files: `useAttachments` and `useFileUpload` for a record's files, `useProfilePhoto` for the person's photo, or the copy-in `attachments` and `avatar-upload` screens. With Vite and tokens in the browser, allow `blob:` in the Content-Security-Policy's `img-src`; with Next.js, keep the BFF's path out of `proxy.ts`'s matcher, as above.

</Step>
<Step>

### Run it

Start the backend first, then:

```sh
npm run dev      # Vite: http://localhost:5173 · Next.js: http://localhost:3000
```

Sign in as the backend's seeded person. The Next.js server reaches the API at `EGRADX_API_URL` (default `http://localhost:8080`).
