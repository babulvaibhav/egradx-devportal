The pattern every business endpoint follows:

1. **Check a permission** — the SDK resolves the caller's permissions on every request.
2. **Take the caller's organization** from the SDK, and scope every query on your own tables to it.
3. **Make the change and record it in the audit trail in the same transaction**, so the record exists exactly when the change does.

The example creates a *note* in a table of the application's own, `acme_note (id, organization_id, title)`. The code is the portal's example applications (`examples/java`, `examples/node`, `examples/python`).

## Your permission, and who holds it

`note.write` is the application's own permission. It goes into the SDK's authority catalog once, at startup, and onto the roles that should hold it — here, every organization's Admin role, through a listener the SDK calls whenever it creates an organization. The example also creates a demo organization, *Demo*, whose administrator is `ada@example.com` (password: `DEMO_PASSWORD`, `demo-password` unless set).
